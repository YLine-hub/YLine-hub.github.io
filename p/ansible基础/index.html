Ansible执行过程

  1. 用户发出Ansible命令（Ad-Hoc或Playbook）

  2. Ansible主程序加载自己的配置文件/etc/ansible/ansible.cfg

  3. 读取主机清单中的设备IP或域名及变量

  4. 调用Ansible命令中的指定的模块，通过Ansible将模块参数生成对应的临时python脚本，传输至目标服务器。

  5. 对应目标主机和执行用户的家目标中出现.ansible/tmp/xxx/xxx.py文件，给改文件赋予可执行权限。执行该脚本并返回结果。

inventory主机清单

ansible的主要功用在于批量主机操作，为了便捷地使用其中的部分主机，可以在inventory file中将其分组命名。 默认的inventory file为/etc/ansible/hosts。 inventory file可以有多个，且也可以通过Dynamic Inventory来动态生成。

主机清单文件格式

inventory文件遵循INI文件风格，中括号中的字符为组名。可以将同一个主机同时归并到多个不同的组中。此外，当如若目标主机使用了非默认的SSH端口，还可以在主机名称之后使用冒号加端口号来标明。如果主机名称遵循相似的命名模式，还可以使用列表的方式标识各主机。

ansible

此工具通过ssh协议，实现对远程主机的配置管理、应用部署、任务执行等功能。

建议：使用此工具前，先配置ansible主控端能基于密钥认证的方式联系各个被管理节点。

范例：利用sshpass批量实现基于key验证

NET=172.16.140
export SSHPASS=magedu
for IP in {1..200};do
    sshpass -e ssh-copy-id $NET.$IP
done

格式：

ansible执行命令的过程

  1. 加载自己的配置文件 默认/etc/ansible/ansible.cfg
  2. 加载自己对应的模块文件，如：command
  3. 通过ansible将模块或命令生成对应的临时py文件，并将该文件传输至远程服务器的对应执行用户
    $HOME/.ansible/tmp/ansible-tmp-数字/xxx.py文件
  4. 给文件+x执行
  5. 执行并返回结果
  6. 删除临时py文件，退出

  • 如果/data/f1.txt不存在，则执行后续命令；如果存在，则不执行后续命令
1

ansible websrvs -m command -a 'chdir=/etc creates=/data/f1.txt cat centos-release'

此时，172.16.140.112和172.16.140.113服务器中，都没有这个文件

  • 在172.16.140.113下创建/data/f1.txt后，再次执行上述命令

touch /data/f1.txt


1

ansible websrvs -m command -a 'chdir=/etc creates=/data/f1.txt cat centos-release'

ip为172.16.140.113的服务器上，执行的命令自动跳过了，因为存在/data/f1.txt文件

  • 如果/data/f1.txt存在，则执行后续命令；如果不存在，则不执行后续命令
1

ansible websrvs -m command -a 'chdir=/etc removes=/data/f1.txt cat centos-release'

刚好返回结果和creates相反，当文件存在，则执行；不存在就自动跳过。

Unarchive模块

功能：解包解压缩

实现有两种用法：

  1. 将ansible主机上的压缩包传到远程主机后解压至特定目录，设置copy=yes
  2. 将远程主机上的某个压缩包解压缩到指定路径下，设置copy=no

常见参数：

  • copy：默认为yes，当copy=yes，拷贝的文件是从ansible主机复制到远程主机上远程主机上，如果设置为copy=no，会在远程主机上寻找src源文件
  • remote_src：和copy功能一样且互斥，yes表示在远程主机，不在ansible主机，no表示文件在ansible主机上
  • src：源路径，可以是ansible主机上的路径，也可以是远程主机上的路径，如果是远程主机上的路径，则需要设置copy=no
  • dest：远程主机上的目标路径
  • mode：设置解压缩后的文件权限

范例：

1
2
3

ansible srv -m unarchive -a 'src=/data/foo.tgz dest=/var/lib/foo'
ansible srv -m unarchive -a 'src=/tmp/foo.zip dest=/data copy=no mode=0777'
ansible srv -m unarchive -a 'src=https://example.com/example.zip dest=/data copy=no'

Lineinfile模块

ansible在使用sed进行替换时，经常会遇到需要转义的问题，而且ansible在遇到特殊字符进行替换时，存在问题，无法正常进行替换。其实在ansible自身提供了两个模块：lineinfile模块和replace模块，可以方便的进行替换。

功能：相当于sed，可以修改文件内容。

范例：

1
2

ansible all -m lineinfile -a "path=/etc/selinux/config regexp='^SELINUX=' line='SELINUX=enforcing'"
ansible all -m lineinfile -a 'dest=/etc/fstab state=absent regexp="^#"'

示例

  • 查看文件/etc/selinux/config
1

ansible all -a 'cat /etc/selinux/config'

可以看到其中的SELINUX值为enforcing

  • 将SELINUX=enforcing改为SELINUX=disabled
1

ansible all -m lineinfile -a "path=/etc/selinux/config regexp='^SELINUX=' line='SELINUX=disabled'"

  • 再次查看所有被控端的/etc/selinux/config
1

ansibel all -a 'cat /etc/selinux/config'

可以看到SELINUX=enforcing已经被修改成了SELINUX=disabled

  • 查看被控端/etc/fstab文件
1

ansible all -a 'cat /etc/fstab'

  • 清空所有被控端/etc/fstab的注释，即删除#开头的内容
1

ansible all -m lineinfile -a 'dest=/etc/fstab state=absent regexp="^#"'

  • 再次查看所有被控端/etc/fstab文件内容
1

ansible all -a 'cat /etc/fstab'

可以看到，注释内容已经被清空了。

Replace模块

该模块有点类似于sed命令，主要也是基于正则进行匹配和替换。

范例：

1

ansible all -m replace -a "path=/etc/fstab regexp='^(UUID.*)' replace='#\1'"
  • 解析：
    • regexp='^(UUID.*)'：正则表达式，匹配以 UUID 开头的行
    • replace='#\1'：替换内容，在匹配行前加 # 注释
    • \1：引用第一个捕获组的内容（整个匹配的行），在上述命令中，\1匹配的是(UUID.*)的内容

示例

  • 查看所有被控端的/etc/fstab文件
1

ansible all -a 'cat /etc/fstab'

  • 让所有被控端的/etc/fstab文件中UUID开头的数据前加#，即注释UUID开头的行。
1

ansible all -m replace -a "path=/etc/fstab regexp='^(UUID.*)' replace='\1'"

  • 再次查看所有被控端/etc/fstab文件
1
