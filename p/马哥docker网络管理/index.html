# Create a network namespace
root@lin-server:~# ip netns add c1-net
root@lin-server:~# ip netns add c2-net

# Creat a veth pair, wich acts as a virtual network cable
root@lin-server:~# ip link add eth1 type veth peer eth2

# Place each end of the veth pair into the two namespaces respectively (like plugging the two ends of a network cable into two boxes)
root@lin-server:~# ip link set eth1 netns c1-net
root@lin-server:~# ip link set eth2 netns c2-net

# Assign IP addresses to the network interfaces in the two namespaces
# ip a a is short for ip address add, which is used to add an IP address to a network interface.
root@lin-server:~# ip netns exec c1-net ip a a 1.1.1.1/24 dev eth1
root@lin-server:~# ip netns exec c2-net ip a a 1.1.1.2/24 dev eth2

# Bring up the network interfaces in the two namespaces
root@lin-server:~# ip netns exec c1-net ip link set eth1 up
root@lin-server:~# ip netns exec c2-net ip link set eth2 up

# Test network connectivity

root@lin-server:~# ip link add veth1 type veth peer veth1-eth0

# Attach veth1-eth0 to the bridge br0

Introduction to Network Modes

Docker supports five network modes:

  • none
  • host
  • bridge
  • container
  • network-name

Bridge network mode

Bridge network mode features:

  • Network resource isolation: Containers on different hosts cannot communicate directly; each uses its own independent network.

  • No manual configuration required: Containers automatically get an IP from the 172.17.0.0/16 subnet by default (configurable).

  • External network access: Uses the host’s physical NIC to connect to the external network via SNAT.

  • External hosts cannot directly access containers: Can be configured via DNAT to accept external access.

  • Relatively low performance: NAT introduces additional network overhead.

  • Port management is cumbersome: Each container requires manually assigned unique ports, leading to port conflicts.

Container mode

Container network mode features:

  • Specified using the –network container:name_or_ID parameter.

  • Isolated from the host’s network namespace.

  • Containers share the same network namespace and directly use each other’s network.

  • The first container’s network may be bridge, none, or host; the second container depends on the first and shares its network.

  • If the first container stops, the second container cannot be created.

  • The second container can access the first via 127.0.0.1.

  • Suitable for frequent network communication between containers.

  • Port mapping is not supported by default and is rarely used.
