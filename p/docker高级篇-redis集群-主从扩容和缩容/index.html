[Docker]高级篇-Redis集群-主从扩容和缩容

2025-12-15

Redis集群（Docker）-主从扩容和缩容

Redis集群部署配置：[Docker]高级篇-Redis集群-3主3从安装配置

主从扩容

新建6387、6388两个节点

  • 创建redis-node-7节点
1

docker run -d --name redis-node-7 --net host --privileged=true -v /data/redis/share/redis-node-7:/data redis:6.0.8 --cluster-enabled yes --appendonly yes --port 6387

  • 创建redis-node-8节点
1

docker run -d --name redis-node-8 --net host --privileged=true -v /data/redis/share/redis-node-8:/data redis:6.0.8 --cluster-enabled yes --appendonly yes --port 6388

  • 查看运行中的容器
1

docker ps

进入6387容器实例内部 

1

docker exec -it redis-node-7 /bin/bash

将新增的6387节点（空槽号）作为master节点加入原集群

  • 将新增的6387作为master节点加入集群
1

redis-cli --cluster add-node 172.16.140.102:6387 172.16.140.102:6381

6387 就是将要作为master新增节点 6381 就是原来集群节点里面的领路人，相当于6387拜拜6381的码头从而找到组织加入集群

语法 

1

redis-cli --cluster add-node 自己实际ip地址:新增的端口号 自己实际ip地址:第一个节点端口号

检查集群情况第1次 

1

redis-cli --cluster check 172.16.140.102:6381

可以看到，虽然在集群中添加了新的master节点，但是并未分配哈希槽。

重新分配槽号

  • 重新分配槽号
1

redis-cli --cluster reshard 172.16.140.102:6381

6381 表示第一个节点

  • 16384分配给四个master节点

16384 / 4 = 4096

  • 分配哈希槽给新节点

  • 全部分配

  • 继续执行重新分配计划

语法 

1

redis-cli --cluster reshard IP地址:端口号

检查集群情况第2次 

1

redis-cli --cluster check 172.16.140.102:6381

槽号分配说明

为什么6387是3个新的区间，以前的还是连续的？

因为重新分配成本太高，所以3家各自匀出来一部分，从6381/6382/6383三个旧节点分别匀出来1364个坑位给新节点6387。

为主节点6387分配从节点6388 

1

redis-cli --cluster add-node 172.16.140.102:6388 172.16.140.102:6387 --cluster-slave --cluster-master-id 1718cdfd0f65f27af32f931313212aea7c365c95
  • 1718cdfd0f65f27af32f931313212aea7c365c95 : 为6387的编号（根据自己的实际情况）

语法 

1

redis-cli --cluster add-node ip:新slave端口 ip:新master端口 --cluster-slave --cluster-master-id 新主机节点ID

检查集群情况第3次 

1

redis-cli --cluster check 172.16.140.102:6381

可以看到redis集群中已经为4主4从。

主从缩容

检查集群情况第一次获得6388的节点ID 

1

redis-cli --cluster check 172.16.140.102:6381

6388的节点ID：2950c24a6ec53b7b534788042540c5397831b12a

从集群中将4号从节点6388删除 

1

redis-cli --cluster del-node 172.16.140.102:6388 2950c24a6ec53b7b534788042540c5397831b12a

语法 

1

redis-cli --cluster del-node ip:从机端口 从机节点ID

检查集群情况第二次 

1

redis-cli --cluster check 172.16.140.102:6382

可以看到redis集群中只剩7台服务器，6388节点已经不见了。

将6387的槽号清空，重新分配，本例将清出来的槽号都给6381

  • 重新分配槽号
1

redis-cli --cluster reshard 172.16.140.102:6381

  • 设置移动的哈希槽数量
1

4096

  • 指定分配给6381的节点
1

9ffebe245719b6aa6a5934e0d81c63402fb4f5ff

  • 告知它使用6387的节点
1

1718cdfd0f65f27af32f931313212aea7c365c95

  • 执行
1

done

  • 继续执行重新分配计划
1

yes

检查集群情况第三次 

1

redis-cli --cluster check 172.16.140.102:6381

4096个槽位否分配给了6381，它变成了8192个槽位，相当于全部都给了6381，不然要输入3次，一锅端。

从集群中将4号主节点6387删除 

1

redis-cli --cluster del-node 172.16.140.102:6387 1718cdfd0f65f27af32f931313212aea7c365c95

检查集群情况第四次 

1

redis-cli --cluster check 172.16.140.102:6381

可以看到恢复成了3主3从的状态。
